# Solovey Contracts

[English](README.md) | [Русский](README.ru.md)

`solovey-contracts` — эталонный репозиторий версионированных семантических контрактов управления для Solovey UI и будущей интеграции с Solovey Node. Репозиторий содержит формальные схемы JSON Schema, сгенерированные модели Go, валидирующий кодек с ограниченной областью применения и эталонные векторы конформантности, используемые независимыми компонентами экосистемы Solovey.

Репозиторий является исключительно спецификацией и библиотекой контрактов. Он не реализует сервер управления, демон исполнения Node, сетевой транспорт, базу данных или привилегированные системные службы.

## Архитектура и границы ответственности

Репозиторий контрактов предоставляет общую семантическую спецификацию, разделяющую плоскость управления (Solovey Panel) и целевую систему исполнения (Solovey Host и будущий Solovey Node):

```text
+-------------------------------------------------------+
|                     Solovey Panel                     |
|  (Оркестрация, сессии пользователей, веб-интерфейс)   |
+-------------------------------------------------------+
                           |
                           | импорт неизменяемого Go-модуля
                           v
+-------------------------------------------------------+
|                   solovey-contracts                   |
|  - JSON Schema 2020-12 (solovey.management/v1)        |
|  - Сгенерированные модели данных Go (managementv1)    |
|  - Строгий валидирующий кодек без внешних зависимостей|
|  - Канонический расчёт дайджестов команд и входных данных|
|  - 115 эталонных векторов конформантности             |
+-------------------------------------------------------+
                           ^
                           | импорт неизменяемого Go-модуля
                           |
+-------------------------------------------------------+
|           Solovey Host / будущий Solovey Node         |
|   (Исполнение на целевом хосте, адаптеры доменов)     |
+-------------------------------------------------------+
```

### Область применения и ограничения

- **Входит в область действия**:
  - Декларативные схемы для команд, ресурсов, мандатов полномочий, возможностей и свидетельств работоспособности.
  - Модели данных на языке Go, строго соответствующие схеме (`types.gen.go`).
  - Строгая детерминированная валидация JSON и расчёт канонических дайджестов (`codec.go`).
  - Фиксированные векторы конформантности для проверки совместимости протокола и инвариантов состояния (`vectors.json`).
  - Инструменты кодогенерации и проверки целостности (`tools/`).
- **Не входит в область действия**:
  - Серверные службы, сетевые слушатели и RPC-диспетчеры.
  - Сетевые транспортные протоколы (HTTP, gRPC, WebSocket).
  - Механизмы аутентификации, генерация токенов MFA и хранилища учетных данных.
  - Хранение состояния в базе данных и транзакционные журналы.
  - Выполнение команд операционной системы, вызовы оболочки (shell) и управление сетевым экраном (`nftables`, `iptables`).
  - Продуктовый агент исполнения Node.

## Ключевые концепции контракта

Контракт `solovey.management/v1` оперирует замкнутыми семантическими структурами с безопасным отказом при ошибках валидации (fail-closed).

### Идентификаторы хостов и ресурсов

- **`HostRef`**: Идентифицирует целевой хост исполнения.
  - Локальный хост: строго `{ "kind": "LOCAL", "id": "local" }`.
  - Удалённый узел (Node): `{ "kind": "NODE", "id": "node:<opaque>" }` со стабильным непрозрачным `NodeID`.
  - Удаление пробелов, синонимы хостов, IP- и MAC-адреса не допускаются в качестве идентификаторов.
- **`ResourceRef`**: Однозначно адресует управляемую сущность в рамках хоста с помощью трёх полей:
  - `host` (`HostRef`): Хост размещения ресурса.
  - `owner` (`string`): Семантический домен-владелец ресурса (например, `data`, `component-lifecycle`).
  - `resourceId` (`string`): Идентификатор ресурса в рамках домена (например, `database`, `component:panel-update-ui`).

### Действия и команды модификации

- **`ActionDescriptor`**: Метаданные, описывающие допустимое действие:
  - `id`: Уникальный идентификатор действия (например, `backup.restore`, `component.remove`).
  - `owner`: Семантический домен-владелец (`data`, `component-lifecycle`).
  - `permission`: Требуемое разрешение.
  - `hostScope`: Граница области действия, строго `TARGET_HOST`.
  - `resourceScope`: Шаблон допустимого целевого ресурса.
  - `riskClass`: Класс эксплуатационного риска (`HIGH`, `CRITICAL`).
  - `inputSchema`: Идентификатор схемы типизированных входных данных.
  - `preview`: Флаг поддержки предварительного просмотра (dry-run).
  - `stepUpPolicy`: Политика повышенной авторизации (например, `existing_browser_one_use`).
  - `auditClass`: Классификатор событий аудита.
  - `revisionFence`: Тип барьера ревизии (`OWNER_REQUIRED` или `OWNER_LIFECYCLE`).
- **`Command`**: Инструкция на изменение состояния, передаваемая целевому хосту. Содержит `contractVersion`, `commandId`, `actionId`, `host`, `resource`, `generation`, `inputSchema`, `inputDigest`, `input`, `correlationId`, `grantRef` и опциональный `expectedRevision`.
- **`CommandDigest`**: Детерминированный хеш SHA-256, вычисляемый по каноническому JSON с отсортированными ключами от полей, влияющих на исполнение (`contractVersion`, `actionId`, `host`, `resource`, `generation`, `inputSchema`, `inputDigest`, `input` и `expectedRevision`). Метаданные доставки (`commandId`, `correlationId`, `grantRef`) исключены из дайджеста, благодаря чему повторная отправка команды со свежими полномочиями не изменяет семантическую идентичность команды.
- **`OwnerInputDigest`**: Канонический хеш типизированных входных данных формата `SHA256(inputSchema + "\x00" + typedInput)`.

### Полномочия и идемпотентность

- **`ManagementGrant`**: Семантический мандат полномочий, связывающий субъекта действия, удостоверяющий центр, действие, разрешение, целевой хост, ресурс, дайджест входных данных, поколения авторизации/учетных данных/MFA, время истечения и одноразовый нонс.
  - JSON мандата не является самоподтверждающимся токеном доступа; полномочия обязательно валидируются авторизационным центром хоста перед исполнением.
- **Идемпотентность и конфликты**:
  - Повторная отправка команды с тем же идентификатором и идентичным дайджестом (`same commandId` + `same CommandDigest`) возвращает сохранённый результат `CommandResult` или `Job` с флагом `replay: true` без повторного выполнения операции.
  - Отправка ранее использованного `commandId` с другим содержимым или намерением приводит к ошибке конфликта (`RESOURCE_CONFLICT` / `INVALID_INPUT`).
  - Передача неактуального или несовпадающего значения `expectedRevision` возвращает ошибку `REVISION_CONFLICT`.

### Наблюдаемость и состояние

- **`Capability`**: Описывает эксплуатационные возможности (`value`: `yes`, `no` или `unknown`). Недоступные факты трактуются как `unknown`.
- **`Change` и `Job`**: Отслеживают жизненный цикл асинхронных операций через состояния `PENDING`, `COMMITTED`, `FAILED`, `ROLLED_BACK` и `RECOVERY_REQUIRED`. Отмена не является принудительной и выполняется только в безопасных точках синхронизации. Прогресс выражается в целых единицах (`completed` / `total`), а не в процентах.
- **`HealthEvidence`**: Ограниченное по времени свидетельство работоспособности. Включает `resource`, `proofKind`, `source`, `observedRevision`, `evidenceRevision`, метку времени наблюдения (`observedAt`) и срок актуальности (`maxAgeSeconds`, в диапазоне от 1 до 60 секунд). Устаревшее свидетельство переходит в статус `UNKNOWN`.
- **`ArtifactTrust`**: Контентно-адресуемая идентичность артефакта (`kind + "\x00" + contentDigest`), прошедшая проверку доверия (`VERIFIED`). Одно совпадение контрольной суммы не формирует доверие без криптографической проверки источника.
- **`SecretRef`**: Маскированная ссылка, подтверждающая наличие и политику секрета в домене владельца без раскрытия чувствительных данных.

## Примеры использования

### 1. Идентификация хоста (`HostRef`)

Локальный хост:

```json
{
  "kind": "LOCAL",
  "id": "local"
}
```

Удалённый узел (Node):

```json
{
  "kind": "NODE",
  "id": "node:worker-node-01"
}
```

### 2. Адресация ресурса (`ResourceRef`)

Ссылка на основную базу данных локального хоста:

```json
{
  "host": {
    "kind": "LOCAL",
    "id": "local"
  },
  "owner": "data",
  "resourceId": "database"
}
```

### 3. Отправка команды изменения состояния (`Command`)

Команда восстановления базы данных с барьером ревизии и связанным дайджестом входных данных:

```json
{
  "contractVersion": "solovey.management/v1",
  "commandId": "cmd-2026-11-09-001",
  "actionId": "backup.restore",
  "host": {
    "kind": "LOCAL",
    "id": "local"
  },
  "resource": {
    "host": {
      "kind": "LOCAL",
      "id": "local"
    },
    "owner": "data",
    "resourceId": "database"
  },
  "expectedRevision": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
  "generation": "7",
  "inputSchema": "solovey.action/backup.restore/v1",
  "inputDigest": "79aa3c625100c984a6a4c562001973c06f9a9ed7d768ece8973d5a758ae19185",
  "input": {
    "rehearsalRevision": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"
  },
  "correlationId": "corr-session-8421",
  "grantRef": "grant-op-4096"
}
```

### 4. Декодирование и валидация документов на Go

```go
package main

import (
	"fmt"
	"log"

	managementv1 "github.com/MalenkiySolovey/solovey-contracts/management/v1"
)

func main() {
	rawJSON := []byte(`{
		"kind": "LOCAL",
		"id": "local"
	}`)

	var host managementv1.HostRef
	if err := managementv1.Decode("HostRef", rawJSON, &host); err != nil {
		log.Fatalf("Ошибка валидации: %v", err)
	}

	fmt.Printf("Успешно валидирован хост: %s (%s)\n", host.ID, host.Kind)
}
```

## Версионирование и совместимость

| Измерение | Идентификатор | Назначение |
| :--- | :--- | :--- |
| **Протокол контракта** | `solovey.management/v1` | Сетевой протокол и спецификация JSON Schema. |
| **Go-модуль** | `v1.0.0` (Semantic Versioning) | Git-теги релизов данного репозитория Go. |
| **Продуктовый релиз** | CalVer (например, `2026.3.2-beta.10`) | Управляется независимо репозиторием `MalenkiySolovey/solovey-ui`. |

### Правила валидации и технические ограничения

- **Замкнутость структур (Closed Objects)**: Неизвестные поля объектов, неописанные схемы действий или непредусмотренные значения перечислений блокируют обработку (fail-closed).
- **Ограничения размера документов**: Максимальный размер документа — 256 КиБ; глубина вложенности объектов — не более 24; количество свойств объекта — не более 48; элементов массива — не более 256.
- **Числовые типы**: Целые числа строго ограничены диапазоном безопасных значений с плавающей запятой: от `-(2^53 - 1)` до `2^53 - 1` (`±9007199254740991`). Счётчики поколений и операций, превышающие этот диапазон, передаются в виде канонических десятичных строк.
- **Строковые идентификаторы**: Допускаются только символы ASCII (`^[A-Za-z0-9._:@+-]+$`), с учётом регистра, без начальных и завершающих пробелов.

## Разработка и проверка

### Требования к окружению

- Go `1.26.10` или совместимый.
- Node.js `24.16.0` (используются встроенные модули стандартной библиотеки; внешние npm-зависимости отсутствуют).

### Команды проверки

Проверка соответствия сгенерированного кода Go схеме без перезаписи файлов:

```bash
node tools/generate.mjs --check
```

Проверка целостности исходного кода, контрольных сумм манифеста и лицензионного происхождения:

```bash
node tools/verify-source.mjs
```

Запуск тестов генератора и векторов конформантности:

```bash
node --test tools/source.test.mjs
```

Запуск модульных тестов Go с детектором гонок данных:

```bash
go test -race ./...
```

Запуск статического анализатора Go:

```bash
go vet ./...
```

### Генерация кода

Для перегенерации моделей Go и контрольных сумм манифеста при изменении схем:

```bash
node tools/generate.mjs
```

## Интеграция в сторонние репозитории

Сторонние компоненты (включая `solovey-ui` и будущие сервисы Node) импортируют публичный Go-пакет:

```bash
go get github.com/MalenkiySolovey/solovey-contracts@v1.0.0
```

```go
import "github.com/MalenkiySolovey/solovey-contracts/management/v1"
```

При интеграции обязательно соблюдение следующих правил:
- Зависимость объявляется только от неизменяемых опубликованных версий (например, `v1.0.0`).
- Контрольные суммы обязательно фиксируются в `go.sum`.
- Запрещается использовать локальные директивы `replace` или копировать код контрактов внутрь зависимых проектов.
- При выполнении проверок в CI необходимо использовать `GOWORK=off` для исключения неявных локальных переопределений.
